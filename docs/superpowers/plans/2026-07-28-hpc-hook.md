# Plan — HPC hook overhaul (own the first five seconds)

_2026-07-28. Branch `hpc-hook`, off `framing-overhaul`._

## Why

Source: [Logan Smith, "How to Make Shorts That Go Viral"] — the **HPC** formula.
**H**ook (first ~5s: introduce the topic, leave questions open) → **P**rogression
(deliver the journey) → **C**limax (pay off, and never early).

Measured against the current pipeline:

- **Climax placement is already right.** `find_hype_moments` takes `peak_pos`
  (0.65) and sets `start = peak − clip_len × peak_pos`, so on a 45s clip the
  audio spike lands ~29s in. That was a good instinct and is not the defect.
- **The hook is unowned.** The first five seconds are, *by construction*, whatever
  happened `clip_len × peak_pos` seconds before the fight — chosen as a pure
  arithmetic offset and **never scored**. In a pro VOD that is almost always
  farming, warding, or walking. The clip opens on its least interesting second.
- **29 seconds of build-up is too long an ask**, and ~35% of every clip (~16s)
  runs *after* the peak, which hurts both average-view-percentage and looping.

## The four changes

### 1. Cold-open teaser (the headline change)

Prepend a ~1.8s flash of the moment just before the spike, then hard-cut back to
the build-up.

**Does this violate "never pay off early"?** No — provided it stays short enough
not to *resolve*. The teaser is cut to **end just after the spike onset**
(`TEASER_LEAD = 1.4s` before the peak, `TEASER_DUR = 1.8s`, so it covers
`peak−1.4 … peak+0.4`). The viewer sees the engage and the caster starting to
yell, then it's gone. That raises the question ("how did that happen?") instead
of answering it, which is exactly what the H in HPC asks for. A teaser long
enough to show the outcome would be the failure mode the video warns about, so
the duration is the safety property here, not a tuning knob to raise casually.

**Implementation — one encode, not two.** The teaser is rendered as a **second
input to the same ffmpeg call** and concatenated in the filter graph, rather than
rendered separately and concatenated on disk:

```
-ss <teaser_start> -t <TEASER_DUR> -i video      # input 0 = teaser
-ss <start>        -t <dur>        -i video      # input 1 = main
-filter_complex
  [0:v] <reframe, suffix=t, static crop, no captions>  [tv];
  [1:v] <reframe, suffix=m, sendcmd + ass + headline>  [mv];
  [tv][mv] concat=n=2:v=1:a=0                          [vo];
  [0:a][1:a] concat=n=2:v=0:a=1, loudnorm=...          [ao]
```

Why not two renders + concat demuxer: `loudnorm` would run **independently** on
1.8s of the loudest audio in the clip and normalize the punch straight back out
of it. One pass keeps a single loudness reference across the whole Short. It also
avoids concat-seam A/V drift from audio priming samples.

Two consequences the code has to handle:

- `build_vf` builds filter graphs with **hard-coded internal link labels**
  (`[a][b]`, `[bg][fg]`, `[pf][hs]`, `[cam][game]`) and a **named** `crop@dyn`
  filter instance. Instantiating it twice in one graph collides on both. It gains
  a `suffix` parameter that renames every internal label *and* the `crop@dyn`
  instance. `suffix=""` must produce a byte-identical string to today's output —
  that is the regression guard.
- The teaser must **not** carry the sendcmd pan (its timeline belongs to the main
  segment) and must not carry captions. It renders with the main segment's
  opening crop x, frozen.

Captions and the static headline are applied on the **main branch, before
concat**, so `.ass` timestamps stay relative to the main segment and need no
shifting.

Gated by `--no-teaser`; on by default.

### 2. Score the opening frame

Replace the fixed `lead_in` offset with a search. Given the per-second smoothed
energy `find_hype_moments` already computes (no extra decode), look in a
`±HOOK_SEARCH` window around the nominal start and take the second with the
highest energy — a shout, an engage call, a first blood ping — so the clip opens
on *something*.

Constrained so the fix can't undo change 1: the peak must still land within
`[HOOK_PEAK_MIN, HOOK_PEAK_MAX]` = 0.55–0.90 of the clip, and the clip must stay
inside the video. Pure function over a numpy array → unit-testable without ffmpeg.

### 3. `clip_len` 45 → 30

29s of build-up is a long ask on Shorts.

### 4. `peak_pos` 0.65 → 0.72 (trim the tail)

Tail drops from ~15.8s (45 × 0.35) to ~8.4s (30 × 0.28) — enough for the
kill confirmation and caster reaction, not enough to decay.

Net shape: **1.8s teaser + 21.6s build + 8.4s payoff = 31.8s**, opening on a
scored frame instead of an arbitrary one.

Defaults change in three places that must agree: `clipper.py` (`make_clips`,
`cut_clip`, argparse), `web/app.py`, `web/templates/index.html`.

## Tasks

1. `build_vf(suffix=...)` — rename internal labels + `crop@dyn`. Test: `suffix=""`
   is byte-identical to the pre-change output for all five layouts; a non-empty
   suffix collides with nothing.
2. `_refine_start` — scored opening second. Tests: picks the local energy max;
   respects the peak-position band; respects video bounds; is a no-op on flat audio.
3. Wire `_refine_start` into `find_hype_moments`.
4. `_teaser_window` + two-input render in `cut_clip`. Tests: window math clamps at
   video start; `teaser=False` produces today's single-input command.
5. Defaults 30 / 0.72 across CLI, web, template. `--no-teaser` flag.
6. End-to-end render test: a synthetic clip renders with a teaser, is
   `TEASER_DUR` longer than the same clip without, and its first frames match the
   climax rather than the opening.
7. Update `HANDOFF.md` + `PROJECT_MAP.md`; commit.

## Risk

`cut_clip`'s render call is the single most load-bearing line in the repo. The
`suffix=""` byte-identity test is what keeps this from silently regressing the
framing work on `framing-overhaul`.
